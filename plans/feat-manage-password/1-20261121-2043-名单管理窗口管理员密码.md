# 名单管理窗口（设置窗口）管理员密码

## Context

`callname/web/manage.html` 是名单管理窗口（主窗口右下角 ⚙ 打开，或 `--manage` 直接启动）。
目前任何人点开都能改名单、权重、清零累计次数。需要：

- 第一次打开设置窗口时强制设置管理员密码；
- 之后每次打开设置窗口都要输入该密码才能进入；
- 忘记密码时有找回手段；解锁后能修改密码。

## 已与用户确认的决策

| 问题 | 结论 |
| --- | --- |
| 首次设置密码的时机 | 首次**打开设置窗口**时（主窗口不拦截） |
| 忘记密码 | 提供 `--reset-password` 命令清空密码 |
| 修改密码 | 解锁后在管理窗口内提供「修改密码」 |
| 分支 | 从 `main` 新建 `feat/manage-password` |

## 设计

### 1. 密码存储与哈希（新增 `callname/auth.py`）

数据库 `meta` 表新增键 `admin_password`，值为 **Argon2id** 哈希串，**绝不存明文**：

```
$argon2id$v=19$m=65536,t=3,p=1$<salt>$<digest>
```

- 用 `argon2-cffi` 的 `PasswordHasher(time_cost=3, memory_cost=65536,
  parallelism=1, hash_len=32, salt_len=16)`（64 MiB），比 `hashlib.scrypt`
  抗 GPU/ASIC 更强，且参数自带在哈希串里。
- 实测（本机）：hash 128 ms / verify 129 ms，只在点「解锁」时跑一次，可接受；
  `p=1` 是 OWASP 的建议，避免低配教室机因核数少反而变慢。
- 校验用 `ph.verify()`，`VerifyMismatchError` / `InvalidHashError` 一律视为失败；
  成功后用 `ph.check_needs_rehash()` 检测参数是否落后，是则透明升级重写哈希。
- 密码长度 4–128 个字符；设置/修改时要求两次输入一致。
- **依赖**：`uv add argon2-cffi`（同时写 `pyproject.toml` 与 `uv.lock`）。已实测
  Python 3.14 可用、带 `py.typed`（strict mypy 直接过）；PyInstaller 自带
  `hook-argon2`（hooks-contrib），Windows 打包无需改 spec。
- **定位说明**（文档里也要写）：这是课堂场景的防误触/防随手改，不是安全边界——
  能读 `callname.db` 的人本来就能改库，js_api 的本地 HTTP 桥也没有鉴权。

`callname/auth.py` 提供 pydantic 之外的纯函数：

```python
hash_password(password: str) -> str
verify_password(password: str, stored: str) -> bool
validate_password(password: str) -> None   # 失败抛 DbError
```

### 2. 数据层（`callname/db.py`）

在 `META_*` 常量旁新增 `META_ADMIN_PASSWORD = "admin_password"`，并加入：

- `get_admin_password_hash() -> str`（复用 `get_meta`）
- `set_admin_password_hash(value: str) -> None`（复用 `set_meta`）
- `clear_admin_password() -> None`（写空串，`configured()` 视为未设置）

不新增数据库迁移：`meta` 已是键值表。

### 3. API 层（`callname/schemas.py` + `callname/api.py`）

**schemas** 新增跨桥模型：

```python
class AuthState(BaseModel):
    configured: bool   # 是否已设置密码
    unlocked: bool     # 当前窗口是否已解锁
```

**ManageApi** 新增内存态 `_unlocked: bool = False`（每个管理窗口是独立进程，
不需要持久化会话），并新增方法（均返回统一信封）：

| 方法 | 行为 |
| --- | --- |
| `auth_state()` | 无需解锁，返回 `AuthState` |
| `setup_password(password, confirm)` | 仅在未配置时可用；校验长度/两次一致；写哈希并**解锁** |
| `unlock(password)` | 校验密码，成功置 `_unlocked=True` |
| `change_password(old, new, confirm)` | 需已解锁；旧密码错误 / 新密码不合法时拒绝 |

**所有业务方法**（`list_people`、`stats`、增删改、导入、`pick_import_file` 等）
入口统一检查解锁态，未解锁直接返回 `LOCKED` 信封。实现上把 `list_people` /
`stats` 也改走现有 `_call()`，在 `_call()` 开头做统一守卫，避免漏掉某个方法。

错误码：`LOCKED`、`BAD_PASSWORD`、`PASSWORD_TOO_SHORT`、`PASSWORD_MISMATCH`、
`ALREADY_CONFIGURED`，中文 message 直接给前端展示。

### 4. CLI（`callname/app.py`）

- `_parse_args` 增加 `--reset-password`。
- `main()` 在 `db.migrate()` 后处理：清空 `admin_password`、`logger.info` 记录、
  返回 0（不创建窗口）。
- 帮助文案写明用途；README 同步说明。这是本地桌面程序的固有取舍：能运行程序
  的人本来就能改 `callname.db`，该命令只是把找回流程做成可发现的。

### 5. 前端

**`manage.html`**

- `.sheet` 初始带 `hidden`，避免未解锁时闪现名单。
- 新增全屏锁屏层（复用 `.modal` / `.modal-card` 样式，另加 `.lock-card`）：
  - 首次：标题「设置管理员密码」，密码 + 确认密码，按钮「设置并进入」；
  - 之后：标题「输入管理员密码」，单个密码框，按钮「解锁」；
  - 错误提示占位、回车提交。
- 工具栏新增「修改密码」按钮 + 独立弹层（旧密码 / 新密码 / 确认新密码）。
- 所有密码框 `type="password"`，设置类 `autocomplete="new-password"`，解锁类
  `autocomplete="current-password"`。

**`manage.js`**

- `boot()`：先 `bind()`，再 `auth_state()`；`unlocked` 为真直接进管理界面
  （同一进程内页面刷新不必重新输密码），否则按 `configured` 显示设置或解锁。
- 解锁成功 → 隐藏锁屏、显示 `.sheet`、再 `loadAll()`。
- 修改密码成功 → toast「密码已修改」。

**`manage.css`**：锁屏层 z-index 高于导入/确认弹层；卡片宽度、输入框沿用
`.input`；错误文案用 `--danger`。

### 6. 测试

**启用前置**：现有 `tests/test_api.py` 直接 `ManageApi(db=db)`，加锁后会被
`LOCKED` 拒绝。在 `tests/conftest.py` 增加 `manage_api` 夹具（`setup_password`
后返回 api），并替换该文件中的构造方式。

新增 `tests/test_auth.py`：

- 哈希往返、错误密码、盐随机（两次哈希不同）、篡改/残缺哈希串返回 False 不抛异常；
- 参数落后的旧哈希校验成功后会被透明重写（升级路径）；
- 短密码 / 两次不一致被拒；
- 未配置 → `auth_state.configured is False`，`list_people` 返回 `LOCKED`；
- `setup_password` 成功后 `unlocked=True` 且能读数据；重复 setup → `ALREADY_CONFIGURED`；
- 错误密码 → `BAD_PASSWORD`；正确解锁；`change_password` 旧密码错误被拒；
- `--reset-password` 对应的 `clear_admin_password()` 后重新变为未配置。

## 验证

- `uv run pytest -q`：83 passed（含新增认证用例）
- `uv run mypy . --explicit-package-bases`：无问题
- 手工（Linux，`xdotool` + `xwd` 截图，不用合成点击）：
  - 空库 `--manage` → 「设置管理员密码」，两次不一致被拒（PASSWORD_MISMATCH）；
  - 设置成功后直接进入名单管理；
  - 关闭重开 → 解锁页；错误密码显示「密码不正确」，正确密码进入；
  - 「修改密码」：原密码 + 新密码两遍 → toast「密码已修改」；重开后
    旧密码被拒、新密码可用；
  - `--reset-password` 后重开 → 回到「设置管理员密码」。
- 主窗口 `--auto 2` 正常，不受密码影响。
